# 3. Core Project Objective

Build an AI agent that receives a user's research or decision-making task and determines what actions are necessary to answer it.

For example:

> "Compare NVIDIA and AMD's latest AI GPUs and tell me which is better for an AI startup with a $10,000 budget."

The agent should be capable of:

```text
User Request
      ↓
Understand Request
      ↓
Decide What Tools Are Needed
      ↓
┌───────────────┬───────────────┬───────────────┐
│ Web Search    │ Calculator    │ Text Analysis │
└───────────────┴───────────────┴───────────────┘
      ↓
Observe Tool Results
      ↓
Determine Whether More Work Is Needed
      ↓
Synthesize Information
      ↓
Final Answer
```

The agent should **not blindly call every tool**.

It should decide which tool is appropriate.

# 5. What Makes This an AI Agent?

A normal LLM application might look like:

```text
User
 ↓
LLM
 ↓
Answer
```

A simple tool-calling application might look like:

```text
User
 ↓
LLM
 ↓
Tool
 ↓
LLM
 ↓
Answer
```

Our application should go further:

```text
User
 ↓
Agent
 ↓
Decision
 ↓
Tool
 ↓
Observation
 ↓
Agent
 ↓
Decision
 ↓
Another Tool
 ↓
Observation
 ↓
Agent
 ↓
Final Answer
```

The important concept is the **control loop**.

The agent receives information, evaluates it, and determines the next action.

# 6. LangGraph Concepts I Must Learn

Before implementing the complete application, I should understand these concepts.

## 6.1 Graph

LangGraph represents an application/workflow as a graph.

A graph contains:

```text
Nodes
Edges
State
```

---

## 6.2 State

State contains information that travels through the graph.

Example:

```python
class AgentState(TypedDict):
    messages: list
    task: str
    tool_results: list
    final_answer: str
    iterations: int
```

The exact state structure should be decided during implementation.

I should understand:

* Why state is necessary
* What information belongs in state
* How nodes read state
* How nodes update state

---

# 7. Nodes

A node represents a unit of work.

Potential nodes:

```text
START
  ↓
Agent
  ↓
Tool
  ↓
Agent
  ↓
Final Response
  ↓
END
```

Possible implementation nodes:

### Agent Node

Responsible for:

* understanding the task
* deciding whether a tool is required
* selecting a tool
* generating tool arguments
* evaluating tool results
* deciding whether more work is required

### Tool Node

Executes the selected tool.

### Final Answer Node

Produces the final user-facing answer.

---

# 8. Edges

Edges determine how the graph moves between nodes.

Simple edge:

```text
Agent → Tool
```

Conditional edge:

```text
Agent
  │
  ├── needs web search → Web Search
  │
  ├── needs calculation → Calculator
  │
  ├── needs text analysis → Text Analysis
  │
  └── enough information → Final Answer
```

I need to understand **conditional routing** rather than simply copying code.

# 12. Agent Decision Process

The agent should follow a controlled decision process.

Conceptually:

```text
START
  ↓
Read User Task
  ↓
Determine Required Action
  ↓
Is information needed?
  ├── Yes → Web Search
  │
  └── No
       ↓
Is calculation required?
  ├── Yes → Calculator
  │
  └── No
       ↓
Is text analysis required?
  ├── Yes → Text Analysis
  │
  └── No
       ↓
Generate Final Answer
```

But eventually the agent should be capable of using **multiple tools sequentially**.

# 13. Controlled Agent Loop

One of the most important parts of the project is learning the agent loop.

Example:

```text
START
 ↓
Agent
 ↓
Web Search
 ↓
Agent
 ↓
Calculator
 ↓
Agent
 ↓
Final Answer
 ↓
END
```

The second Agent invocation receives the previous tool output.

It asks:

> "Do I have enough information?"

If yes:

```text
→ Final Answer
```

If no:

```text
→ another tool
```

---

# 14. Prevent Infinite Loops

A major requirement is to make the agent reliable.

Never allow:

```text
Agent → Tool → Agent → Tool → Agent → Tool → ...
```

without a limit.

Add:

```python
MAX_ITERATIONS = 5
```

or an appropriate configurable value.

Example:

```text
iterations = 0

Agent
 ↓
Tool
 ↓
Agent
 ↓
Tool
 ↓
Agent
 ↓
Tool
 ↓
Iteration limit reached
 ↓
Final response
```

The exact implementation should be decided while building it.

I should understand **why** the limit exists.

### Case 3 — LLM fails

The application should return a meaningful error instead of crashing.

### Case 4 — User asks something unsupported

Example:

> "Book me a flight to London."

The agent does not have a flight-booking tool.

It should say that the current agent cannot perform that action.
